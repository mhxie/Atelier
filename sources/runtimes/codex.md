## Codex capability baseline

Checked: 2026-09-10. Documentation baseline, with explicit CLI version
boundaries where published. Local app, standalone CLI, IDE and hosted Work are
different hosts; this file does not assert local enablement or successful use.
Apply the [evidence contract](README.md) when comparing observations.

| Facet | Documented surface and important conditions | Primary source |
|---|---|---|
| instructions | User and nested project `AGENTS.md`; `AGENTS.override.md` takes precedence in its directory. Project instructions require trust from CLI 0.150.0. | [Instructions](https://learn.chatgpt.com/docs/agent-configuration/agents-md), [releases](https://learn.chatgpt.com/docs/changelog) |
| settings | User `config.toml` and trusted project `.codex/config.toml`; machine-local provider/auth/telemetry settings cannot be overridden by project config. Named profiles use separate profile config files. Trust does not remove execution approvals. | [Configuration](https://learn.chatgpt.com/docs/config-file/config-basic), [reference](https://learn.chatgpt.com/docs/config-file/config-reference) |
| subagents | Project/user `.codex/agents/*.toml`, one named role per file. Native collaboration is documented for local hosts; actual tools and inherited permissions remain session-dependent. Delegation follows explicit user or applicable instruction authority. | [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) |
| skills | Project `.agents/skills` and user `~/.agents/skills`; symlinks supported. Repository-local `.codex/skills` is removed in 0.148.0. Do not infer removal of user compatibility locations from that project change. | [Skill discovery](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills), [releases](https://learn.chatgpt.com/docs/changelog) |
| commands | Built-in CLI `/model`, `/permissions`, `/skills`, `/agent` and `/hooks` coexist with `$skill` invocation. User custom prompts are deprecated; skills are the documented replacement. | [Commands](https://learn.chatgpt.com/docs/developer-commands), [custom prompts](https://learn.chatgpt.com/docs/custom-prompts) |
| hooks | `.codex/hooks.json`, inline `[hooks]` and plugin hooks. Script directories are not independently discovered. Config layers compose; project trust and hook-definition trust are separate. Post-tool hooks cannot undo effects. | [Hooks](https://learn.chatgpt.com/docs/hooks) |
| mcp | `[mcp_servers.*]` for local hosts supports STDIO and Streamable HTTP with authentication conditions. Hosted Work does not read local configuration. The standalone `mcp-server` subcommand is removed in CLI 0.154.0; this does not remove MCP client support. | [MCP](https://learn.chatgpt.com/docs/extend/mcp), [0.154.0 release](https://learn.chatgpt.com/docs/changelog) |
| permissions | Approval/reviewer policy, sandbox, managed requirements and execution rules are separate. All `.rules` under active layers' `rules/` are scanned; `default.rules` is the TUI write target. Network domain rules require the proxy and do not govern hosted web/apps/MCP. | [Rules](https://learn.chatgpt.com/docs/agent-configuration/rules), [permissions](https://learn.chatgpt.com/docs/permissions) |
| output-style | Claude-style output-style directory discovery is not documented. Instructions, skills and supported personality controls express related needs, not the same package format. | [Communication style](https://learn.chatgpt.com/docs/config-file/config-basic#communication-style) |
| plugins | Root `plugin.json` is the portable manifest; `.codex-plugin/plugin.json` remains a supported compatibility fallback. Installation, enablement, authentication and hook trust are distinct gates. | [Packaging](https://developers.openai.com/plugins/build/plugins) |
| workflows | Skills author reusable workflows. Native Scheduled execution depends on host, plan and availability; desktop scheduling needs the machine/app online. A dedicated Claude-style workflow-script directory is not documented. | [Skills](https://learn.chatgpt.com/docs/build-skills), [Scheduled](https://learn.chatgpt.com/docs/automations) |
| status-line | CLI/TUI `/statusline` and `tui.status_line` display selected session data. Project/profile scope remains unverified here; generic config precedence does not establish support for every TUI field. Display is not historical telemetry. | [Status line](https://learn.chatgpt.com/docs/developer-commands#configure-footer-items-with-statusline), [schema](https://learn.chatgpt.com/docs/config-schema.json) |
| memory | Generated local memory is experimental and off by default, with separate usage/contribution controls. Hosted Work has different memory controls. Required rules belong in checked-in instructions, not inferred memories. | [Memories](https://learn.chatgpt.com/docs/customization/memories), [defaults](https://learn.chatgpt.com/docs/config-file/config-basic#common-feature-flags) |
| sessions | CLI resume/fork and `exec resume` operate on conversation state. Persistence is required for later saved-session recovery; `--ephemeral` avoids rollout persistence. Fork is not a separate filesystem or rollback. | [CLI session controls](https://learn.chatgpt.com/docs/developer-commands#codex-resume), [noninteractive sessions](https://learn.chatgpt.com/docs/non-interactive-mode#resume-a-non-interactive-session) |
| isolation | Desktop Git worktrees separate checkouts while sharing Git metadata. CLI `--worktree` is experimental from 0.154.0. Neither worktrees nor cleanup recovery snapshots isolate credentials, network or external effects. | [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees), [releases](https://learn.chatgpt.com/docs/changelog) |
| checkpoints | Desktop Git controls revert selected changes. General transactional checkpoint/undo equivalence is not documented; deprecated app-server `thread/rollback` changes conversation history, not documented filesystem restoration. | [Git controls](https://learn.chatgpt.com/docs/environments/local-environment#use-built-in-git-tools), [thread rollback](https://learn.chatgpt.com/docs/app-server#roll-back-recent-turns) |
| collaboration | Native subagents can be instructed, awaited, inspected and stopped; they incur usage and inherit boundaries. This does not imply automatic worktrees, durable scheduling or identical hosted Work controls. | [Collaboration](https://learn.chatgpt.com/docs/agent-configuration/subagents) |
| observability | `exec --json` exposes lifecycle/items and completion usage, separate from schema-constrained final output. Native OTel exports are opt-in and machine-scoped; prompt redaction alone does not remove all tool-result content. Token counts do not prove billed cost or useful outcomes. | [JSONL](https://learn.chatgpt.com/docs/non-interactive-mode#make-output-machine-readable), [OTel](https://learn.chatgpt.com/docs/config-file/config-advanced#observability-and-telemetry) |
| channels-monitors | Generic Claude-style Channels/Monitor equivalence is not documented. Evaluate lifecycle hooks, app-server events or supported scheduled triggers against the actual need. App-event triggers are host-specific; Goal mode is not a scheduler. | [App-server events](https://learn.chatgpt.com/docs/app-server#events), [event triggers](https://learn.chatgpt.com/docs/automations#trigger-tasks-from-app-events), [goals](https://learn.chatgpt.com/docs/long-running-work) |
